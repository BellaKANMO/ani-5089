Ce qui est stable : l'écart entre l'instant prédit et maintenant vaut toujours exactement une période déclarée (16,667 ms à 60 Hz, 13,889 ms à 72 Hz, 11,111 ms à 90 Hz, 8,333 ms à 120 Hz), puisque le code l'obtient par une addition : il ne prouve rien. Ce qui est stable aussi, c'est le rythme réel des images : environ 10 ms quelle que soit la fréquence déclarée, car c'est l'écran qui le fixe, pas MASALLE_HZ. Ce qui n'est pas stable, c'est l'écart entre le début réel de l'image suivante et l'instant prédit : -7,059 ms à 60 Hz, -3,670 ms à 72 Hz, -1,103 ms à 90 Hz, +1,520 ms à 120 Hz. Il change parce que la prédiction suit la fréquence que je déclare, et non celle de l'écran. Elle n'est juste que si la fréquence déclarée est celle de l'écran.

Un sur la fréquence : 1000 / 60 = 16,667 ms ; 1000 / 72 = 13,889 ms ; 1000 / 90 = 11,111 ms ; 1000 / 120 = 8,333 ms. Ce sont bien les quatre périodes affichées par le programme.

La période de mon écran : réel - prédit = période de l'écran - période déclarée, donc période de l'écran = (réel - prédit) + période déclarée. À 60 Hz : -7,059 + 16,667 = 9,608 ms. À 72 Hz : -3,670 + 13,889 = 10,219 ms. À 90 Hz : -1,103 + 11,111 = 10,008 ms. À 120 Hz : 1,520 + 8,333 = 9,853 ms. La moyenne des quatre valeurs est (9,608 + 10,219 + 10,008 + 9,853) / 4 = 9,922 ms, soit 1000 / 9,922 = 100,8 Hz. Les réglages de Windows indiquent <valeur> Hz.
