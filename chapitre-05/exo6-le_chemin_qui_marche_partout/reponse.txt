What changed : Le code de rendu est identique dans les quatre essais. Seul change le dossier courant : un chemin relatif comme murs/photo.jpeg part du dossier d'où le programme est lancé. Depuis projet/, murs/ existe et la texture charge (567x1008). Depuis Build/Bin/Debug-Windows/projet/, murs/ n'existe pas (je l'avais renommé en murs_off pour l'essai) : le moteur écrit "Echec chargement texture : murs/photo.jpeg" et le mur reste magenta, la texture de secours du moteur. L'erreur vient donc du dossier courant, pas du rendu. Le programme ne plante pas : l'échec n'apparaît que dans le journal et par cette couleur, ce qui le rend facile à manquer.

What LocateResource tries : D'après le commentaire de NkPath.h, dans cet ordre : 1. le dossier courant ; 2. le dossier de l'exécutable ; 3. les parents de l'exécutable, 8 niveaux au plus ; 4. les parents du dossier courant, 8 niveaux au plus. Dans chaque dossier, toutes les variantes sont essayées avant de passer au suivant. Elle renvoie le chemin absolu trouvé, ou une chaîne vide si rien n'est trouvé ; avec warnIfMissing à true, un avertissement au journal liste alors les dossiers essayés. Dans mes essais, depuis projet/, elle a trouvé murs dans le dossier courant (étape 1) ; depuis Build, elle l'a trouvé à côté de l'exécutable (étape 2). Mon code teste Empty() avant d'afficher ou d'utiliser le chemin.
